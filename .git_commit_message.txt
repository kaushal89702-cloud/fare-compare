Fix: diagnostics were being generated but hidden by the UI itself

Two real bugs found from "just says no fares can be read, nothing in red":

1. ComparisonScreen only rendered the per-provider progress/diagnostics
   list while isRunning was true. The instant every provider finished
   (success or fail), isRunning flipped to false and that entire section -
   including any red diagnostics text - disappeared, leaving only the
   generic "No fares could be read" summary line. Diagnostics were very
   likely being captured the whole time; they were just never visible.
   Fixed: the list now shows whenever there is any provider progress to
   show, regardless of isRunning.

2. The FareNotFoundBeforeTimeout / NoRidesAvailable failure path (the one
   that produces exactly the "no fares can be read" message) called
   failureDiagnosticsRecorder.captureFailure(...) but discarded its
   result instead of storing it in lastDiagnosticsSummary. So even with
   bug #1 fixed, this specific failure would still have shown nothing.
   Fixed: its diagnostics summary is now captured and attached to the
   failure exactly like the pickup/destination-not-found paths already
   did.

Tested: ./gradlew assembleDebug and testDebugUnitTest both green (34
tests, unchanged). Please test again - the Comparison screen should now
show red diagnostics text under each failed provider for every failure
type, including "no fares found". Send that text back if it's still
blank; if it now shows something, send the exact text so the field/fare
keyword lists can be corrected precisely.
